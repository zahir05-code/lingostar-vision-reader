# LingoStar MVP 품질 보증 및 테스트 검증서 (QA_Tester)

작성일: 2026년 05월 27일

본 문서는 **LingoStar Vision Reader**의 기능 정합성, 저시력 접근성 엣지 케이스, 데이터와 UI/UX 간의 연동 무결성을 사전에 검증하기 위한 QA 점검 시나리오를 정의합니다.

---

## 1. 기획-아키텍처-DB-UI/UX 교차 무결성 검증 (Cross-Check)

5대 핵심 영역의 설계 사양들이 서로 모순되거나 데이터 형식이 엇갈리지 않았는지 최종 점검(Incremental QA)합니다.

| 점검 영역 | 설계 내용 | 일치 여부 및 검증 의견 |
|:---|:---|:---|
| **기획 ↔ 아키텍처** | 문장 파싱 및 단락 압축 데이터의 처리 흐름 | **일치**. 아키텍처 팀의 `textParser.js` 유틸이 문장 기호를 분해하여 `sentences` 배열로 제공하므로 기획 요건을 안전하게 충족합니다. |
| **아키텍처 ↔ DB** | Firebase Firestore 스키마 매핑 및 LocalCache | **일치**. DB 팀의 `passages` 내 `sentences` 스키마가 AppContext 상태 구조와 정확히 매치하여 쿼리 호출이 최소화됩니다. |
| **DB ↔ UI/UX** | 읽기 진행률(Sentence Index) 실시간 업데이트 | **일치**. 문장 이동 시 `currentSentenceIndex` 값을 Firestore `readingProgress`에 연동하고, 오프라인 상태 시 캐시 보존을 적용합니다. |
| **UI/UX ↔ 기획** | 5종 접근성 테마 및 72px 거대 UI 버튼 | **일치**. CSS Variables HSL 명세를 준수하여 고대비(AAA 등급)를 보장하고, 72px 규격의 BigButton을 배치합니다. |

## 2. Happy Path 시나리오 테스트 케이스

### TC-01: 신규 영어 지문 등록 및 쪼개기 학습 시작
- **시나리오**: 교사나 학생이 홈페이지에서 긴 영어 지문을 붙여넣고 "학습 시작"을 탭합니다.
- **예상 결과**:
  1. `textParser.js`가 문장을 성공적으로 쪼개어 Firestore `passages` 컬렉션에 새 문서로 등록합니다.
  2. 사용자는 집중 읽기 모드(`FocusReadingPage`)로 자동 리다이렉트됩니다.
  3. 첫 번째 문장이 40px 크기로 화면 중앙에 초대형 렌더링되며, 하단에 72px 크기의 거대 [다음 문장] 버튼이 나타납니다.

## 3. 저시력/접근성 엣지 케이스 테스트 케이스

### TC-02: 글자 크기 최대치(64px) 및 모바일 해상도(320px) 충돌
- **시나리오**: 학생이 가로 폭이 좁은 스마트폰에서 글자 크기를 최대치인 64px로 설정합니다.
- **테스트 목적**: 한 단어가 너무 길어 가로 스크롤이 생기거나 버튼과 글자가 겹쳐 누르지 못하는 현상이 예방되었는지 확인합니다.
- **검증 기준**:
  - CSS에 `word-break: keep-all; overflow-wrap: break-word;` 속성이 반영되어 단어가 잘리지 않고 자연스럽게 다음 줄로 흐르며(Reflow), 스크롤 바 없이 세로 영역이 유동적으로 확장되어야 합니다.

### TC-03: 고대비(High Contrast) 모드 활성화 시 인지성
- **시나리오**: `highContrast` 테마를 적용하고 미니맵 및 내비게이션 요소들을 탭합니다.
- **검증 기준**:
  - 검정색(#000000) 배경에 밝은 노란색(#FFFF00)의 강렬한 텍스트 대비가 100% 명도 만족을 하는가?
  - 포커스를 이동했을 때 선명한 Yellow 포커스 링(4px)이 생성되어 현재 선택 위치가 뚜렷이 확인되어야 합니다.

---

## 4. 종합 QA 승인 여부
- **총평**: 5대 핵심 파트 간의 정합성이 완벽하며, 저시력 아동의 특수한 신체 조건에 따른 오터치 및 시인성 에러 요인들이 기획서와 CSS 명세 단계에서 모두 예방되어 있으므로 **설계 단계 품질 보증(QA Approval)을 전격 승인**합니다.
